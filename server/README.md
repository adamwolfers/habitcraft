# HabitCraft server (Go)

The Go server that replaces `backend/` in the rebuild (habitcraft-vxln; see
[README.md](../README.md#direction)). It is an embeddable Go package plus a
standalone binary, and its HTTP interface is generated from
[`shared/api-spec/openapi.yaml`](../shared/api-spec/README.md).

**Status:** this is the skeleton (habitcraft-vxln.3). `/health` and `/hello`
work. Every other operation answers `501 Not implemented` until its bead lands:
auth in habitcraft-vxln.4, then users, habits and completions in
habitcraft-vxln.5. The stubs are in `habitcraft/unimplemented.go`, so move each
method out of that file as you implement it.

## Layout

| Path | What it is |
|---|---|
| `api/` | Generated by oapi-codegen: types, the strict server interface, the embedded spec. Never hand-edit `api.gen.go` |
| `habitcraft/` | The embeddable package: `habitcraft.New(Config)` and `Server.Handler()` |
| `internal/validation/` | Validates every request against the spec before a handler sees it |
| `cmd/habitcraft/` | The standalone binary |

## Running

```bash
# From the repo root: the test database on :5433, migrated by db-migrate-test
docker compose -f docker-compose.test.yml up -d postgres-test db-migrate-test

cd server
DATABASE_URL='postgresql://habituser:habitpass@localhost:5433/habitcraft_test?sslmode=disable' \
  go run ./cmd/habitcraft            # listens on :8080; PORT overrides
```

The schema is `db/migrations/`, applied by dbmate exactly as for the Node
backend. The server never migrates the database itself. To build a binary, use
`go build -o bin/habitcraft ./cmd/habitcraft`. `bin/` is gitignored, and a bare
`go build ./cmd/habitcraft` fails because the output name collides with the
`habitcraft/` package directory.

## Testing

```bash
go test -race ./...        # unit tests; the database is faked
../scripts/go-lint.sh      # gofmt and go vet, as CI runs them
```

These are phases 12 and 14 of `scripts/test-all.sh` and the
`server-unit-tests` CI job. The acceptance suite runs against this server with
`ACCEPTANCE_API_URL=http://localhost:8080 ACCEPTANCE_BACKEND=go` (see
[acceptance/README.md](../acceptance/README.md)). It is only worth running once
the auth endpoints exist, because every test registers a user first.

## The spec is load-bearing here too

Three things tie the server to `openapi.yaml`:

- **Strict handlers.** Each method of `api.StrictServerInterface` returns one of
  its operation's generated response types, so a status or body the spec does
  not document will not compile.
- **Request validation.** `internal/validation` checks every request's
  parameters and body against the embedded spec (habitcraft-sb0). It answers a
  failure with a 400 in whichever error shape that operation documents:
  `ValidationErrors` for the auth and user routes, `DetailedError` for habits,
  `Error` for completions. That matters because the acceptance suite checks
  every response body against the spec. A test sends a request that cannot be
  valid to each operation and checks the answer the same way. kin-openapi
  ignores `format: email` and `format: uuid` unless they are registered, so
  the package registers both. The email check has no local-part length cap, so
  an address at the spec's `maxLength` is accepted (Node's habitcraft-0roi bug).
- **Codegen.** `api/api.gen.go` is regenerated and diffed by
  `npm run api:codegen -- --check` with the TypeScript consumers' files. Regenerate
  with `npm run api:codegen` from the repo root, or `go generate ./...` here.
  Both use `api/oapi-codegen.yaml` and produce the same file. oapi-codegen is
  pinned as a `tool` in `go.mod`.

Authentication is not part of request validation. The spec declares two
alternative schemes on each protected operation, `cookieAuth` and `bearerAuth`.
Authentication will run as its own middleware in front of validation, so an
anonymous caller gets a 401 before any field is checked, as on the Node backend
(habitcraft-vxln.4).

## Embedding

```go
server, err := habitcraft.New(habitcraft.Config{DB: pool}) // a *pgxpool.Pool
handler, err := server.Handler()
mux.Handle("/", handler)
```

The handler's paths are absolute (`/health`, `/api/v1/...`), as the spec writes
them. To mount it under a prefix, wrap it in `http.StripPrefix`. The in-process
API for embedding applications is habitcraft-vxln.6.
